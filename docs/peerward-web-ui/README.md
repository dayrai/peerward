# Peerward Web UI（设计参考原型）

本目录是独立的静态设计参考，包含模拟设备、共享和交互状态，不连接 Control API。
页面中的加入命令、二维码和操作结果用于演示，不是可用的设备接入凭据或运行证据。
实际产品使用 [`apps/peerward-console`](../../apps/peerward-console/) 的 Rust/Dioxus
实现；部署和操作请以[控制台指南](../web-console-guide.md)为准。
以下各轮记录描述设计演进，不能单独作为当前代码的功能验收结论。
真实流程与 API 的逐项映射见[2026-09-21 原型对齐记录](../analysis/console-prototype-alignment-2026-09-21.zh-CN.md)。

这是面向 **单管理员、多 Mesh** 使用方式的 Peerward Web 管理界面原型。目标不是继续堆功能，而是让日常操作按任务和风险分层，同时保持与 Peerward 底层 Mesh 资源模型一致。

## 核心变化

### 1. “共享”升级为真正的 Mesh 资源入口

“共享”仍然是用户看到的统一入口，但底层区分三类资源：

- **设备服务**：映射到 `Service`。例如 NAS SMB、Dashboard、SSH。
- **局域网资源**：映射到 `NetworkResource + GatewayBinding`。例如打印机、摄像头、局域网主机或网段。
- **互联网出口**：映射到 `Exit`。由网关 Peer 提供受控的 SNAT 出口。

新增共享时先选择共享类型，再填写该类型真正需要的字段。

### 2. 状态不再简单写成“可用 / 不可用”

资源详情现在拆成四层：

1. **配置**：共享设置是否已经保存。
2. **授权**：是否存在允许访问的 Policy。
3. **连接**：提供设备或网关是否在线，当前网络连接路径是否存在。
4. **可达性**：实际服务端口、局域网目标或互联网出口是否可达。

这样可以避免把“已经配置”误解成“此刻一定能访问”。

### 3. Relay 语义校正

界面现在把两个层级明确拆开：

- **问题与维护**：只处理当前 Mesh 的 Presence、直连、Relay 备用和网关路径问题。
- **系统工具 → 系统维护**：管理 Control、Relay Host、数据库，以及容量、备份、升级和部署诊断。

Relay Host 不再被表现成“某个 Mesh 专属的一台 Relay”。同一基础设施可以承载多个 Mesh 的逻辑上下文；共享主机的维护动作因此不会混在日常网络排障里。

### 4. 设备身份更新语义校正

控制台不再写“管理员轮换设备凭据”。现在改为：

> **请求设备更新身份**

在线设备收到请求后自行更新身份材料；控制台不会替设备生成或保存私钥。撤销凭据仍然属于高风险操作。

### 5. 平台范围与当前 1.0 设计一致

演示数据和加入设备流程只展示：

- Linux
- Android

Windows、macOS、iOS 不再作为当前可加入平台出现在原型操作中。

### 6. 访问权限保持独立

访问页仍然回答最简单的问题：

> 哪台设备 / 哪个设备组，可以访问哪个共享？

默认流程改成 **先选设备或设备组 → 再看这个来源的访问结果 → 点“查看原因”看解释**，不再先铺满整张矩阵。共享可以是设备服务、局域网资源或互联网出口。高级 Policy 和具体条件模拟仍保留，不会用简化结果静默覆盖底层规则语义。

### 7. 高频操作按“任务”串起来

日常使用不再要求管理员自己理解页面之间的依赖关系：

- **添加设备**：创建一次性邀请 → 在设备端使用 → 回到控制台核对身份 → 批准 → 打开设备详情。
- **添加共享**：共享什么 → 谁可以访问 → 预览确认 → 查看共享状态或继续检查访问。

邀请方式、有效期、DNS、站点标识等仍然保留，但默认收进高级选项。共享详情点击“检查访问”会带上当前资源上下文；全局搜索中的设备组也仍可直接定位为访问来源。

### 8. 对象详情按使用频率和风险分层

设备详情不再把工程字段和凭据操作铺在第一页，顶层只保留：

> **状态 → 共享与访问 → 维护**

默认状态页只显示虚拟地址、系统和位置说明；名称与位置通过状态页的小入口修改。Peer ID、客户端版本、连接方式等进入“技术详情”；凭据更新、撤销和停用集中在“维护”，设备记录也在维护页按需展开。

共享详情顶层固定为：

> **状态 → 设置 → 网关路径**

“状态”继续展示配置 / 授权 / 连接 / 可达性四层证据；普通修改进入“设置”，暂停/恢复与普通字段分开；只有局域网资源和互联网出口显示“网关路径”；底层类型、地址和原始数据收进状态页的“技术详情”。

### 9. 跨页面任务保留上下文

真实 Console 中，设备和共享详情把选中对象写入 URL，因此刷新后仍能打开同一对象；从列表打开详情后，浏览器“返回”或关闭详情都会回到原列表并保留该次页面会话里的筛选状态。

设备进入完整“访问”页时保留当前设备作为来源；共享进入“访问”页时保留当前共享作为目标。访问页用明确的上下文条说明“从哪里来”，并提供返回设备或共享详情的入口。普通保存完成后也给出“返回状态 / 查看状态”的下一步，而不是让管理员停留在编辑表单。

### 10. 异常按“影响 → 下一步”处理

“问题与维护”不再只罗列错误名称。每个事项固定给出：

> **发生了什么 → 现在影响什么 → 建议先做什么 → 进入哪个对象处理**

设备离线、设备身份即将到期、共享无网关路径、目标不可达、配置被设备拒绝等状态都遵循同一表达。正常的默认拒绝和访问拦截仍记录在活动中，但不会混进故障待办。

处理完成后不直接显示“修复成功”。管理员回到“问题与维护”点击 **重新检查**，由新一轮证据判断结果：事项消失才显示当前证据已经恢复；仍存在就继续保留。这样“请求更新身份”“保存设置”“重启设备”等动作和真正恢复状态不会被混为一谈。

安装级状态默认保持安静：没有异常时只确认“共享基础设施当前无待处理事项”；真正影响多个 Mesh 的 Control / Relay Host / 备份 / 审计观测问题才引导进入 **系统工具 → 系统维护**。

### 11. Round 8：整体验收以“减法”为主

这一轮不再增加新的日常入口，而是删掉重复表达：侧栏只给“问题与维护”保留数字提醒；概览只保留设备和共享两张常驻统计卡；网络拓扑移到“问题与维护”的排障折叠区；设备导出藏进“更多”；共享页移除长期占位的资源模型说明和统计条；问题页把数量直接合并进“待处理 / 已知 / 全部”筛选。

设备、共享和访问页底部原先较大的“高级工具”说明卡也压缩成一行入口。能力没有删除，但正常管理网络时不再需要先读一段底层概念。

### 12. Round 9：最后一公里统一

日常页面统一使用 **网络 / 设备 / 共享 / 访问 / 中继服务** 这组词。`Mesh`、`Peer`、`Presence`、`Policy`、原始凭据等底层术语只在技术详情、系统维护或开发文档中出现，普通管理员不需要先理解协议模型才能完成任务。

异步状态也改成统一反馈：**正在读取、没有数据、没有匹配结果、读取失败、操作完成** 各自表达，不再把“加载中”和错误同时显示。首次没有设备或共享时直接给下一步；筛选无结果时只建议调整条件；可恢复错误提供就地“重试”。已知 API 错误默认隐藏内部错误码，未知错误仍保留代码以便排障。

窄屏设备列表不再依赖横向滚动，保留设备名称、简要信息与状态；显示/语言设置统一收进账户菜单，减少顶栏噪声。

## 运行

解压后直接打开 `index.html` 即可；无需安装依赖。

该版本仍是交互原型，示例数据不会写入真实 Peerward 后端。

## 建议优先体验

1. 打开 **共享**，切换“设备服务 / 局域网资源 / 互联网出口”。
2. 打开 **客厅打印机**，查看“配置 / 授权 / 连接 / 可达性”四层状态。
3. 打开 **家庭互联网出口**，观察网关路径和 SNAT 语义。
4. 点击 **添加共享**，体验三种共享类型的不同创建流程。
5. 打开 **访问**，选择一台设备或设备组，查看它对不同共享的最终访问结果。
6. 打开 **问题与维护** 查看当前连接路径，再进入 **系统工具 → 系统维护** 查看共享基础设施。
7. 打开设备详情 → **维护**，体验“请求设备更新身份”，并观察高风险操作如何与普通设置分开。

### 13. Round 10：发布前五场景验收

这一轮不再调整主架构，而是按 **首次使用 / 正常状态 / 异常状态 / 只读权限 / 手机窄屏** 五类真实场景做发布前收口。

- **首次使用**：空页面只给当前用户真正能做的下一步。可写账号可以直接加入设备或添加共享；只读账号不再收到“去添加”的错误引导，只说明数据出现后可以在哪里查看。
- **正常状态**：继续保持安静，不增加新的常驻统计或系统状态。首页、设备、共享和访问页仍以“有没有事情需要处理”为优先。
- **异常状态**：沿用“发生了什么 → 影响什么 → 建议下一步 → 重新检查确认恢复”的闭环，不把“点击过修复按钮”误当作恢复成功。
- **只读权限**：真实 Console 会明确显示“只读模式”，隐藏“添加设备 / 添加共享 / 修改访问”等变更入口；高级入口也改成“高级…信息”，避免让查看者误以为可以执行维护动作。
- **手机窄屏**：访问结果不再保留桌面三列表格的横向滚动，而是堆叠成卡片；共享、访问结果和详情都有移动端标签，详情抽屉占满可用宽度。

这五类场景是后续发布前回归的固定基线。新增能力如果让只读账号看到不可执行操作、让空状态给出错误下一步，或重新引入手机横向滚动，都应视为界面回归。


### 14. Round 11：发布候选的“死路”审查

这一轮按完全不了解 Peerward 内部模型的单管理员路径逐项检查，不新增主功能，重点删除会让人误以为“还要再选一次”或“已经是当前状态”的界面死路。

- **设备详情中的访问结果固定当前设备**：不再重复显示来源搜索和来源下拉框；需要比较其他设备或设备组时，再进入完整“访问”页。
- **未选择网络不再误判为“首次创建”**：概览只引导“选择一个网络”；真正的网络列表为空时，再根据权限分别提示“新建网络”或“当前账号不能新建网络”。
- **添加共享继续去资源模型化**：普通步骤使用“共享类型 / 共享内容 / 查看共享状态”，不再要求管理员先理解“资源定义”这一层内部表达。
- **全局搜索只显示人类可读类型**：后端的 `device / group / service / subnet / internet` 不直接出现在搜索结果中，而统一显示为“设备 / 设备组 / 共享 / 网络”。
- **详情读取失败不伪装成当前状态**：设备详情给出就地重试；共享详情若只能保留上次已加载的信息，会明确标注“这是旧信息”，重新检查成功前不能当作当前状态。
- **访问来源读取失败可恢复**：设备和设备组候选加载失败时显示独立错误与重试，不再留下一个看似正常但实际缺数据的空选择框。
- **普通页面进一步使用“设备身份”**：维护和问题提示优先描述“设备身份是否有效/需要更新”；凭据序列、原始凭据等只保留在技术详情或高风险撤销操作中。
- **操作记录不再裸露内部 action 名称**：例如 `peer.update` 在设备详情中显示为“设备 · 修改”；底层稳定 action 仍保留在审计数据与技术排障能力中。

这轮的验收标准是：从主页面进入任意详情后，普通管理员都能回答“我现在在看谁、这是不是当前数据、下一步能做什么”，而不需要根据禁用控件、内部枚举或错误码自行推断。

### 15. Round 12：交互安全与键盘无障碍

主信息架构保持冻结，这一轮只处理“操作时会不会误丢内容、键盘能不能完整走通、状态变化能不能被辅助技术正确感知”。

- **详情抽屉和弹窗形成真正的模态焦点范围**：打开后焦点留在当前窗口内，关闭后回到刚才触发它的按钮；背景内容不再参与键盘焦点。
- **设备和共享详情使用标准 Tab 语义**：状态、共享与访问、维护、设置、网关路径都带 `tablist / tab / tabpanel` 关系，并支持方向键、Home、End 切换。
- **未保存修改覆盖更多入口**：邀请的加入方式/有效期、共享向导中的类型与高级项、授权、设备身份更新、退役等表单在离开前都会提示；仅打开一个确认表单而未填写内容不会误报“有未保存修改”。
- **提交过程防重复操作**：保存、预览、授权、更新身份、退役等请求在进行中禁用相关字段和提交按钮，并显示“正在保存 / 正在检查 / 正在提交”等明确状态；提交进行中不允许误按 Escape 或关闭按钮把操作窗口提前关掉。
- **成功和失败使用不同语义**：失败使用 `role="alert"`，成功或完成提示使用 `role="status"` / `aria-live="polite"`，避免屏幕阅读器把成功消息读成错误。
- **减少动态效果**：系统启用“减少动态效果”后，参考原型和真实 Console 都会关闭不必要的动画与平滑滚动。

Round 12 的验收原则是：不用鼠标也能完成“打开详情 → 切换任务 → 修改 → 保存/取消 → 返回”，且任何异步提交都不会因为连续按 Enter 或重复点击而发出第二次请求。

## Round 13：发布候选冻结

从这一轮开始，主导航、详情层级和日常术语视为冻结。后续 UI 变更只用于修复真实构建、Playwright、键盘/无障碍、权限或恢复演练发现的缺陷，不再通过增加统计卡、技术字段或重复入口来“完善”页面。

发布候选统一使用 `scripts/run-release-candidate.sh console` 绑定 core 验证、v14 浏览器回归和部署契约检查；更重的本地演练使用 `full`。可再生截图继续只写入 `artifacts/`，不回填 `docs/evidence`。正式发布清单、升级/回滚边界与已知限制见 [`../release-candidate.zh-CN.md`](../release-candidate.zh-CN.md)。

### 2026-09-21：添加设备改为选择设备组

按确认后的产品流程，第一步保留设备名称、设备平台，以可选多选的设备组替代设备用途；默认不分组。选择时展示所选组已有共享授权。原型完成入网时加入所选组，基本信息保留名称和位置说明。原型数据用于交互演示，真实控制台在服务端入网事务中提交成员关系，并依据实际访问规则执行授权。
