# Peerward 产品化路线图

更新：2026-09-08。本文是产品与工程建议，不代表以下功能已经交付。
当前版本与发布通道见 [release.toml](../release.toml)；运行验收以
[动态 Mesh 实施记录](dynamic-mesh-implementation.md)为准，稳定发布以
[发布证据规则](release-evidence.md)为准。

## 目标与首批用户

长期目标是达到 Tailscale、NetBird 同类产品的可用性、可维护性和可信度。
用户进一步明确第一阶段服务个人与家庭，连接家庭设备、智能体和长期记忆服务。
早期试用优先面向有 NAS/家用服务器经验的家庭；开发者是初始使用者，而非最终产品边界。
详细定位、应用授权边界和首版验收故事见[家庭智能体与记忆网络](home-agent-network.zh-CN.md)。
将外部 agent harness 作为接入对象，具体职责、claw-code 核查与适配契约见
[Harness 接入规划](harness-integration.zh-CN.md)。
企业与嵌入式市场不同时作为首发目标。

首个完整体验：家庭成员在外安装客户端并认领邀请，使用自己的智能体只读查询家中授权资料，
知道内容来源、查看访问结果并撤销后续访问；切换网络、重启、升级和退出都有可理解的结果。
普通用户无需编译 Rust、手工编辑网络配置或理解中继协议。

可验证的产品定位是：家庭资料可在本地保管、成员与智能体按授权使用、容易自托管、
多个独立信任域、部署资源不随 Mesh 增删、故障原因清楚。
这些是 Peerward 应交付的价值，不作为竞品缺少对应能力的断言。

| 家庭与智能体 | 设备身份、网络隔离与服务访问基础 | 成员和智能体分别授权、资料集合权限、可撤销委托、记忆服务参考集成；当前网络 ACL 不提供内容级授权 |

| 发布运维 | 签名更新、回滚、备份恢复工具和发布检查 | 实际发行物、独立构建、长稳、容量、外部安全审计等完整证据 |

## 默认部署与使用体验

默认部署为一台服务器运行 PostgreSQL、Control、Console、共享 Relay，设备运行 Peer。
服务器可以在云上，也可以是对目标设备可达的本地服务器；默认不要求另一层 WireGuard 隧道。
云 Relay、本地 Control/数据库作为数据位置有明确要求时的高级方案。
保留 Compose；本路线图不重新引入 Helm、Docker socket 或每 Mesh 容器。
HTTPS 入口、身份提供方等辅助服务按需存在，不用“恰好四容器”限制必要的认证交付。
家庭原始记忆与本地应用默认位于 NAS/家用服务器，不进入组网数据库；云端推理的内容流向
由用户在应用中明确选择。新增智能体不要求新增核心容器，应用工作负载单独管理。

对用户承诺的操作应是：

1. 从发行渠道安装客户端，完成登录或认领，后台服务自动启动。
2. 看到真实的连接状态、设备地址和能访问的资源。
3. Docker 应用可将端口绑定到 Mesh IP；回环服务可使用服务转发。
   两种方式都要通过访问策略，界面解释它们的区别；容器转发需做真实 Docker 网络验收。
4. 能解释“设备离线”“策略拒绝”“应用没监听”“DNS 失败”“正在中继”等不同原因。
5. 退出或撤销后恢复系统网络；未收到撤销的离线设备仍遵循已确定的离线策略。
6. 记忆服务分别验证成员和智能体的资料访问权限；撤销应用委托不等同于删除 Mesh 或原始资料。

公开部署必须完成生产认证配置，不能把自动附加开发管理员 bearer 的 Console 直接暴露。
邀请认领入口与管理权限分别验证；手机扫描的链接不能指向管理员电脑的 localhost。

## WireGuard 技术决策

当前数据通道与信任边界见 [协议说明](protocol.md) 和 [架构说明](architecture.md)；历史选型讨论可从 Git 历史查阅。
已确认以 GotaTun 0.9.2 / Rust 1.95.0 迁移设备间数据会话，保留 Peerward 的身份、策略与共享 Relay。
独立适配层已有内核互通和标准换钥长流证据，完整契约、两端运行时与穿透承载仍待完成；
详见[实施记录](analysis/wireguard-migration-status.zh-CN.md)：工作区 Linux 已接入共享 WG 与加密协调，Android 正式入口及新 Relay 承载仍待完成，发布门保持关闭。
WireGuard 负责加密会话；Peerward 仍负责授权、签名目录、地址、ACL、发现、中继和生命周期。
采用 WireGuard 不会自动解决 NAT 穿透、移动端后台运行或产品整体的安全问题。

迁移按基线、引擎准入、身份版本契约、两端运行时、穿透承载、切换交付推进；每步保持可构建：

| 必须解决的问题 | 原型应给出的证据 |
| --- | --- |
| 独立 Root 与 WireGuard 公钥绑定 | 凭据绑定 Mesh、设备、公钥、序列号和有效期；验证后才能安装允许的公钥与地址；拒绝跨 Mesh、过期、撤销和回滚状态 |
| 两种路径保持端到端加密 | 两端 WireGuard 密文经直接 UDP 或共享 Relay 传输，Relay 无需设备私钥；外层路由元数据有独立认证与限额 |
| Mesh 隔离与固定部署 | 使用隔离的密钥、路由和生命周期上下文；上下文可卸载，不因 Mesh 数量增加宿主端口或容器 |
| 权限与平台适配 | Linux 内核和用户态路径分别记录策略执行位置；不能只用 AllowedIPs 代替端口级访问策略；验证 Android 套接字保护与系统 VPN 生命周期 |
| 换钥、撤销与路径变化 | 区分会话密钥更新与设备身份轮换；验证凭据重叠时的精确吊销、代理异常后的授权失效、旧公钥退出、删除持久化和网络切换，记录既有 TCP 是否中断 |
| 实现与维护选择 | 记录维护状态、平台支持、依赖许可、更新策略和集成边界；已确认保持 Rust 运行时，并保留指定版本依赖许可 |

不修改标准 WireGuard 握手来塞入现有前导。保留的管理/Relay 控制协议与设备间数据协议
分别标明版本；使用标准 WireGuard 数据格式也不等于原生 WireGuard 客户端能自动认领 Peerward Mesh。
如果采用新引擎，更新协议规范、测试向量、发布元数据和 SPEC.lock，新增数据库迁移，
制定客户端能力协商与拒绝降级规则。开发实例允许重建，不延伸为正式用户数据可以丢弃。
阻断性互通或生命周期问题解决前不发布切换版本；切换后不提供旧设备数据协议回退。

## 分阶段交付

| 阶段 | 具体交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0：明确产品入口与技术方向 | 家庭验收故事、成员/设备/智能体/服务权限模型、默认部署指南、WireGuard 决策原型、统一基准方法 | 两台真实 Linux 设备完成加入与访问；用记忆服务原型证明网络授权和资料授权分别执行；数据引擎原型有直连、中继、撤销和隔离结果，形成技术决策 |
| P1：可邀请家庭试用 | HTTPS 与生产认证安装、Linux/Android 包、一种可替换的记忆服务集成、智能体只读委托、Console 状态与访问事件 | 两名成员、一个家庭节点和一个智能体通过查询来源、私人集合隔离、禁止写入、撤销与备份恢复验收；手机用自身移动网络加入 |
| P2：真实环境稳定与桌面扩展 | NAT/IPv6/受限网络测试、Android 实机矩阵、Windows 客户端；随后按用户反馈安排 macOS/iOS | 每个已宣称支持的平台独立完成安装、重启、换网、升级、退出和恢复；不能以 Linux 结果替代 |
| P3：稳定发布 | 容量报告、24 小时多 Relay 长稳、独立构建、安全审计、升级恢复和支持文档 | 仓库全部稳定发布门槛对同一提交和发行物有效，已知问题与支持范围明确，无伪造或跳过证据 |
| P4：扩大产品适用范围 | 根据家庭试用结果增加更多记忆连接器、受控写入、多节点备份协作；子网、出口和团队功能按需安排 | 每项有目标用户和独立验收，资料处理责任明确，不把所有智能家居能力塞入基础安装路径 |

P0 的测量工作与安装体验修复可以并行，但替换数据引擎依赖技术决策。
P0 同时设计成员委托与 harness 适配契约；P1 的家庭查询必须通过一个实际 harness 完成。
claw-code 为候选，不是核心服务的强制依赖；其实际 MCP 互通未验证前不得标为支持。
工具权限、会话恢复后的重新授权和原文/会话分离纳入 P1；其他候选 harness 独立验收。
Linux/Android 是首批闭环，不代表已经与竞品的全平台覆盖持平。
排期需要结合贡献者数量、设备和独立审计资源确定，本文不承诺固定日期。

## 验收与对比方法

比较 Peerward 当前实现、WireGuard 原型、固定版本的 Tailscale 和 NetBird。
记录提交/版本、操作系统、CPU、内存、MTU、规则、网卡卸载配置和中继位置。
内核与用户态结果分开列出；纯 WireGuard 的直连成绩不能与完整产品的远距离中继成绩混比。
每个场景至少重复五次，保留所有结果与失败；将配置后首次连接、稳态传输和换网恢复分别计时。

| 验收维度 | 场景和记录 |
| --- | --- |
| 上手体验 | 从干净机器安装到第一次获准访问的时间、手工步骤、失败原因；首批建议至少 5 位未参与开发的试用者 |
| 家庭记忆访问 | 两名成员个人/共享集合隔离、智能体最小委托、来源核对、拒绝越权与写入、撤销后新请求拒绝；验证服务端执行，不能只检查聊天回答 |
| Harness 兼容 | 固定上游提交，实际工具调用与来源返回；任务重启/fork 后权限不扩大，shell/插件不绕过授权；确定性工具测试与真实模型运行结果分别记录 |
| 连通性 | 同 LAN、家宽 NAT、双重/对称 NAT、移动网络、IPv6、禁止 UDP；记录测试次数、直连/中继/失败比例及恢复时间，不能归并为无条件“穿透率” |
| 数据性能 | 直连与同位置中继分别测 TCP/UDP、小包/大流、双向/并发流；记录吞吐、RTT p50/p95/p99、丢包、CPU、RSS、FD 与云端字节数 |
| 移动体验 | 实体 Android Wi-Fi/移动网切换、锁屏、Doze、VPN 权限撤回、进程回收；固定设备与测试时长比较空闲/活动耗电 |
| 隔离与恢复 | 跨 Mesh、伪造来源、撤销、旧版本、恶意前导；删除 A 时 B 的同一流持续，控制/数据库/Relay 故障后不会复活已删除状态 |
| 运维与增长 | 保留 100 次生命周期循环及 100 Mesh 固定容器回归；另按实际承诺的活跃 Peer/流量测容量；升级与备份恢复验证身份和配置一致 |

性能门槛在基准环境和首轮数据确定后写入决策记录，再用于实现验收；不能根据最终结果反向挑选有利场景。
外部安全评审与平台实测是独立工作，不由 benchmark 或单元测试代替。
遵循已有约定：云主机无需完整 Android 构建；构建和实机证据在合适的开发/测试环境产生。
这些环境未到位时保留缺失状态，不宣称产品化验收完成。

## 对照资料

Tailscale 将 WireGuard 与控制服务结合，并提供直连和中继连接路径；它的产品能力并非仅由隧道协议构成。
参见 [Tailscale 产品原理](https://tailscale.com/docs/concepts/what-is-tailscale)和
[连接类型](https://tailscale.com/docs/reference/connection-types)。
NetBird 同样在 WireGuard 之外提供管理、信令与中继，参见
[NetBird 工作原理](https://docs.netbird.io/about-netbird/how-netbird-works)。
以上资料核对日期为 2026-09-08，不据此推断 Peerward 已达到相同可靠性或性能。
