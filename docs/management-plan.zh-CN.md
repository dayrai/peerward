# Peerward 管理方案与操作流程

适用：家庭、一人公司、小微企业；以 Peer（设备）为管理主线，不设计用户、组织或复杂 RBAC。沿用既有管理认证、能力授权与审计来源。核对日期：2026-09-14。

本文同时说明**当前可用入口**和**目标操作方案**。五入口、局域网资源与规则表单已接入代码，受控接入与设备生命周期已接入，出口与 P3 等仍在实施；当前实现与运行证据以[实施清单](management-implementation-status.zh-CN.md)为准。参考依据、代码入口和差异清单见[参考核对与取舍](management-reference-review.zh-CN.md)。

阅读时分别看两个维度：实现状态使用“已有 / 部分具备 / 待实现”；验证状态说明“静态核对 / 有测试代码 / 有指定版本运行证据”。原始核对以静态审查为基线；本轮模块、数据库与网络实验记录单独列在实施清单中。不能由文档或测试文件的存在推导生产可用。

## 1. 快速开始：先完成一次真实访问

### 1.1 当前版本可以怎样开始

当前工作区版本见 [release.toml](../release.toml)，保留 Schema 4、Wire 5，仅支持全新部署；阶段完成与验证结果见[实施清单](management-implementation-status.zh-CN.md)。以下任务卡的现状标签在相应闭环通过后更新。Peer 产品范围为 Linux、Android。部署与实际命令沿用[Linux 快速上手](cloud-local-linux-quickstart.zh-CN.md)、[本地部署](local-linux-deployment.zh-CN.md)和[Android 说明](android.md)，不在此复制另一套安装过程。

| 步骤 | 当前操作 | 完成依据 |
| --- | --- | --- |
| 准备网络 | 已有可用 Mesh 直接使用；新部署在当前“Mesh”页面走自动创建，等待任务完成 | Mesh 可用，签发材料与 Relay 分配已就绪；创建记录本身不代表完成初始化 |
| 加入设备 | 当前“入网票据”页面创建邀请；Linux 导入后运行 Peer，Android 扫描后核对并确认 | 核销成功、配置保存、客户端实际连接；每台设备使用自己的邀请 |
| 准备应用 | 在提供设备上启动应用，直接绑定实际 Mesh IP，或使用已有本地服务发布能力 | 应用监听及提供设备上的转发确实存在 |
| 允许访问 | 当前“策略”页面选择来源 Peer、目标 Peer、协议与所需端口，校验后保存 | 规则结果符合预期；新 Mesh 默认拒绝 |
| 验证结果 | 从获准设备访问应用；已注册 Service 可先做策略模拟 | 实际应用访问成功，未授权来源或端口被拒绝 |

当前普通 Peer、服务端口访问不要求先实现局域网路由或出口功能。二维码里的控制服务地址必须从受邀设备可达；电脑浏览器能访问的 `localhost` 地址不能直接用于手机入网。公网接入部署沿用既有 HTTPS 与认证要求。

## 2. 五个入口与页面组织

### 2.1 导航及现有入口映射

控制台已采用五入口，邀请位于设备下，Relay、Authority 和审计位于运维下，Mesh 设置位于顶部。网络共享新增局域网资源表单，访问规则新增资源规则与测试，Mesh 设置新增 DNS 配置。旧链接继续定位原页面；工作区实现尚需完整浏览器验收。

| 目标入口 | 页面内容 | 主要操作 | 当前入口如何承接 |
| --- | --- | --- | --- |
| 概览 | 当前网络健康、设备概况、待处理事项、重要告警 | 添加设备、查看原因、处理任务 | 复用概览；只显示已有可靠数据，补充分层状态 |
| 设备 | 设备列表；邀请记录与待审批申请；统一设备详情 | 添加、改名、标签、诊断、停用 | 合并设备与入网票据；完整邀请历史和审批队列待实现 |
| 网络共享 | 设备服务、局域网资源、互联网出口三个页签 | 创建共享、选择提供设备、批准、验证 | 服务承接当前服务页；局域网资源表单已接入；互联网出口待完成后开放 |
| 访问规则 | 规则编辑、模拟、发布记录；集合与测试按需展开 | 来源 → 目标 → 服务或端口 → 检查并发布 | 复用策略编辑与模拟；资源规则的保存断言、发布预览、历史草稿及集合已接入；完整操作验收待补齐 |
| 运维 | 诊断、Relay、凭据与信任、审计、任务、备份升级、可选自动化 | 排障、查看执行结果、维护 | 合并 Relay、审计、高级 Authority；已有任务与工具先提供清晰入口 |

Mesh 设置从顶部当前网络进入；只有一个 Mesh 时隐藏切换器，保留网络名称和设置入口。设置包含基本信息、地址与 DNS、策略默认值、生命周期及恢复材料说明。高级手工模式不放在普通用户的必经路径中。

### 2.2 各页应回答的问题

- **概览**：先列阻断操作的问题，再列容量提醒。每条事项显示影响、观测时间和下一步；“控制服务可访问”“设备在线”“应用可用”分别展示。配置关系图不表示实际通信流量。
- **设备**：列表展示显示名称、虚拟地址、受控标签、管理状态、在线观测与更新时间；详情集中展示服务、凭据、诊断和关联规则。待实现的网关能力、应用回执不得伪造为现有字段。
- **网络共享**：目标、提供设备、批准、当前路径、可用性和访问范围放在同一详情。由设备详情进入共享操作时带入提供者；由共享进入规则时带入目标。
- **访问规则**：常用服务预设辅助填写端口，保持底层语义可见；高级规则不能完整呈现时转到高级编辑，不静默简化。
- **运维**：默认显示需处理的失败任务和到期事项；公钥、序列号、版本与原始诊断放在详情。私钥和票据秘密不成为普通可查看字段。

### 2.3 所有操作共用的交互约定

| 场景 | 目标行为 |
| --- | --- |
| 进入对象操作 | 自动带入 Mesh 和对象；选择器显示名称，重名时以地址、标签或短 ID 消歧，完整 UUID 放详情 |
| 普通编辑 | 必填项最少；就地校验，保存后保留当前上下文；不反复确认普通改名 |
| 搜索与筛选 | 支持名称、地址、标签、状态；按当前 Mesh 分页；筛选后明确显示条件和结果数，不把当前页当作全部 |
| 空状态 | 无设备时“添加设备”；无服务时说明先在提供设备启动或发布；无规则时解释默认动作；受筛选隐藏时提供清除筛选 |
| 未交付或不支持 | 文档明确标为待实现；产品不展示可点击的占位动作。已分配但不受支持的配置显示原因 |
| 离线设备 | 保留可编辑元数据及最后观测；修改不显示已在离线设备应用，不因离线自动撤销长期设备 |
| 敏感操作 | 展示对象、影响及恢复方式；沿用现有目标名称或精确凭据核对，避免普通编辑也套用同样确认 |
| 批量操作 | 先选对象、预览数量与影响，再提交；当前限同 Mesh、同资源族的 1–100 个对象，任一冲突则整批不提交 |
| 异步操作 | 保存后显示任务及阶段；刷新仍可查；同一失败任务重试，不用重复创建对象来“重试” |
| 错误反馈 | 显示原因、对象、下一步与请求关联标识；保留输入，不把接口内部异常直接倾倒到页面 |
| 基本可用性 | 可用键盘操作；表单有标签；状态不只靠颜色；错误可定位到字段，异步结果可被辅助技术感知 |

## 3. 常用任务操作卡

以下“入口”为目标五入口；“现状”同时标明当前可执行路径。新能力的流程用于实施与验收，不是当前按钮说明。

### 3.1 添加一台设备

**入口与输入**：设备 → 添加设备。当前先进入入网票据页并选择 Mesh；最低只需确认有效期，默认五分钟、单次使用。

**步骤**：创建邀请 → 当次结果显示链接或二维码 → 在受邀客户端导入 → 核对网络及信任信息 → 确认入网 → 启动连接 → 回到设备详情命名并设置必要标签。Android 扫码只产生预览，必须保留显式加入与系统 VPN 权限确认。

**成功与失败**：核销后看到 Peer 和凭据，客户端连接才算完成接入。签发机构不可用时引导检查 Mesh 初始化；链接不可达时检查客户端实际可达地址；过期或已取消时重新签发。相同签名核销请求重试应恢复原结果，不重新生成身份来碰撞单次票据。

**现状与待补齐**：已接入 QR、原子双地址核销、预设名称/受控标签、普通/预绑定/审批三种互斥模式。列表和详情显示保留范围内的完整历史与关联设备，秘密仍只在创建时返回。已支持长期、临时和限期设备；邀请有效期与访问截止时间分别配置。控制台创建 Peer 记录不作为普通添加设备路径；完整平台运行证据见[实施清单](management-implementation-status.zh-CN.md)。

Linux 使用 `peerward join accept --bundle-file <受限文件> --output-dir <新目录>`；`--bundle-file -` 从标准输入读取。位置参数保留，但会暴露给命令历史或进程参数采集；脚本和 CI 应使用受限文件或标准输入，不回显邀请。

### 3.2 通过核验批准设备（已接入，平台验收继续）

**入口与输入**：设备 → 待审批申请；创建邀请时选择核验模式，最少绑定目标 Mesh、期限及可信核验依据。

**步骤**：设备提交签名申请 → 显示待核验 → 管理员通过可信渠道比对身份公钥指纹 → 批准 → 原子完成登记与签发 → 客户端取回结果并连接。未批准申请不领取可通信凭据或拓扑；首版不预占正式虚拟地址。

**成功与失败**：批准必须绑定原请求、密钥和版本；申请被修改、过期、取消或票据状态冲突时重新核验。相同批准重试返回同一结果；拒绝后不偷偷释放票据给另一申请抢用。待决申请需要独立标识、有限保留时间与限流；票据预留与終态已由数据库事务约束，客户端取回响应后仍须核验凭据和实际连接。

**边界**：设备自报名称、来源 IP 与普通“批准”点击不是身份证明。PoP 只证明对应密钥的签名；短 TTL 和受保护交付减少泄露，不能抵抗已泄露票据被其他密钥抢用。要求抗抢用的场景必须配套可信公钥预绑定或带外核验，作为该场景上线前提。

已实现接口为 `GET /api/v1/meshes/{mesh}/join-applications`、单项查询及其 `/approve`、`/reject` 操作；修改需要现有写权限和 `If-Match`。批准请求必须携带通过可信渠道核对的完整 `identity_fingerprint`。创建邀请的 `settings.mode.kind` 只能为 `bearer`、`prebound` 或 `approval`；预绑定模式额外提供该指纹。审批前返回 HTTP 202，客户端每五秒重发同一签名请求；申请独立有效三十分钟。批准、双地址分配、凭据签发、规范响应和审计同事务提交，重复批准不重复建设资源。

Linux 可先运行 `peerward join prepare --output-dir <新配置目录>` 获取指纹，再使用同一目录执行 `peerward join accept --bundle-file <受限邀请文件>`（另需 `--output-dir`）。临时状态位于相邻的私有 `.peerward-join` 目录，首次 HTTP 请求前落盘，并使用进程锁防止重复提交；网络失败或终止后，重新提供同一邀请和目录即可继续。成功写入配置后清理临时私钥文件。Android 的“准备设备身份 / 查看指纹”提供相同预绑定入口，原签名请求使用本机密钥加密保存在不参与系统备份的目录，失败后保留。两平台的预绑定及审批均需要可信带外核对，不能防止泄露票据被抢先占用造成拒绝服务。

### 3.3 共享 NAS 或设备上的服务

**入口与输入**：网络共享 → 设备服务；最低选择提供 Peer、协议和端口，名称或别名按需填写。

**步骤**：先在提供设备启动应用。应用可直接绑定实际 Mesh IP；仅监听本机回环地址时，Linux 可用 `peerward service publish` 发布本地转发。两种方式选择适合应用的一种，避免同一端口重复占用。已有本地发布不要求再手工创建重复目录记录。随后设置来源设备及访问规则；已注册 Service 用现有模拟器检查，再从来源设备验证实际访问。

**成功与失败**：应用访问成功且未授权访问被拒绝。目录有记录但无法连接时，检查本地发布、进程监听、协议、端口、策略和宿主网络；不重复创建记录。没有注册为 Service 的普通 IP/端口访问仍可配置 Peer 规则；扩展模拟接口可选择真实 Peer 或资源及具体地址、协议和端口。来源设备须已完成地址分配，模拟不代表应用在线。

**现状与边界**：已有服务目录、TCP/UDP 本地发布、别名和策略模拟。控制台登记 Service 不会远程启动应用或自动建立本地转发；取消目录发布也不等于关闭宿主机程序。现有 Service 依附一个 Peer，不是稳定虚拟地址加多后端的负载均衡服务。

### 3.4 访问打印机或摄像头（P1 部分具备）

**当前状态**：资源、绑定、批准、规则及 DNS 表单已接入真实 API，已运行隔离数据库与浏览器操作测试；Linux 转发已运行独立命名空间测试。完整 WireGuard/Relay 产品网络、Android 动态消费与双地址分配仍待验收，不能据此标记 P1 完成。

**入口与输入**：网络共享 → 局域网资源 → 创建；填写名称、目标 IP/CIDR、所需协议端口，选择网关。默认单网关、SNAT；优先单主机资源，避免为一台打印机开放整个 LAN。

**步骤**：例如创建 `192.168.1.50/32` 打印机资源 → 选择办公室网关 → 核验平台、目标可达性和前缀冲突 → 批准绑定与发布范围 → 授权访客到 TCP/631 → 分发给需要的客户端 → 客户端接受路径 → 检查路由、网关转发、回程及实际打印。

**成功与失败**：打印通过，网关管理口及其他未授权目标被拒绝；不能把“批准”作为业务通过证据。冲突时指出具体路径和地址范围；拒绝不支持的异站点重叠，提示调整地址或使用独立活动配置。不能自动退回更宽子网或互联网出口。IP 需固定或用 LAN 的 DHCP 保留，避免地址换机后权限指向另一设备。

**边界**：CIDR ACL 不自动提供子网转发。网关标签不能代表打印机身份；转发授权和网关本机访问分别检查。TCP/631 规则不能区分同端口打印与管理页面；管理接口还需应用认证。三层路由不自动转发广播、mDNS/SSDP，也不保证打印机自动发现。

更换网关时保留资源 ID，核验新绑定、批准并验证，再撤回旧绑定；审批权威来源只有一份。首次交付不同时开放多个活动提供者。

### 3.5 使用家庭或公司互联网出口（P2 实施中）

**入口与输入**：网关设备申请出口能力 → 网络共享中批准；使用者在客户端选择已获准出口。默认不强制所有设备使用。

**步骤**：核对网关能力与可用性 → 批准提供者、使用范围和地址族 → 客户端主动选择 → 显示有效 IPv4、IPv6、DNS 及本地网络例外 → 验证实际出口和故障阻断。

**成功与失败**：所选流量经过预期出口；出口中断时保持受保护模式并阻断相关公网流量，显示“出口不可用，等待恢复”。允许用户明确退出出口模式，不能静默回落直出。未覆盖地址族不得悄悄泄露；需要本地 LAN 或网络登录页时显式显示例外。

**Linux 当前操作**：使用当前配置文件明确选择本机网络。`peerward client exit list --config peer.toml` 列出已批准的出口；`peerward client exit select --config peer.toml --resource office-exit` 按唯一名称或 UUID 选择，自动要求接管 DNS，默认关闭本地 LAN 例外。`peerward client preferences --config peer.toml` 查看保存版本、系统应用状态和原因。该状态不替代实际业务验证。

`peerward client set --config peer.toml --accept-routes false` 关闭私网路径接受；`--dns false` 关闭 DNS 接管（已选择出口时拒绝该组合）；`--inbound false` 拒绝新的设备入站连接。设置沿用本机受保护套接字的操作系统身份认证，按版本保存，重复原请求不产生新版本。

主动退出使用 `peerward client exit off --config peer.toml`。守护进程异常退出后，先停止对应服务，再执行 `peerward client exit off --config peer.toml --offline`：取得独占运行锁、恢复自有路由和 DNS，最后解除防直出规则。离线退出不要求未过期凭据；清理失败继续保留阻断。若退出过程再次中断，应重试显式退出，普通启动不会根据旧偏好自动解除遗留保护。

底层连接从创建套接字时标记旁路，控制/Relay/STUN 名称仅经配置允许的启动解析器解析；普通 DNS 查询不能使用该旁路。Linux 使用独立路由表与精确恢复日志，发现冲突的策略路由时拒绝启用并说明原因。已批准资源撤回、出口故障或地址族不被提供者覆盖时，继续捕获流量并由核心拒绝。Linux 双栈子网/出口/DNS/强杀恢复的完整隔离实验已通过；Android 已接入消费和持久恢复，尚未完成模拟器与真机出口验收。

**Android 当前操作**：连接设备后打开“设置 → 连接偏好与互联网出口”，选择出口并保存。切换出口自动开启网络 DNS，默认不允许本地 LAN 例外；来源名称和地址族覆盖显示在选择项中。界面分别显示持久版本、应用状态与原因，缺少有效授权时显示未知。版本冲突保留草稿，可明确重新读取后重试。关闭出口是本机偏好变化，不撤销管理员批准。

Android 保存偏好使用同一原生核心的版本与幂等模型，私有文件按 Mesh/Peer 保存。恢复时先读取选择，TUN 捕获 IPv4/IPv6 后才开始报文处理；新增出口选择先扩大捕获，再持久化意图。TUN 或 DNS 更新失败保留已有捕获并报告拒绝。应用回执包含配置与本地偏好两个版本，旧回执不能确认新选择。API 28 的本地 LAN 例外使用有界前缀扣除，网内设备和已管理资源的精确路由仍保留。

**平台保护等级**：Linux 出口安装独立、可恢复且进程退出后保留的防直出规则，只有主动退出模式才清理。Android 默认只保证 VPN 有效运行期间：出口链路故障时保留 TUN 并阻断；进程终止、VPN 被撤销或系统接管失效后可能恢复直出。前台服务不是持续阻断保证。

Android 高级模式引导用户进入系统 VPN 设置，开启“始终开启 VPN”和“阻止未使用 VPN 的连接”；API 29 起查询 `VpnService.isAlwaysOn()` 与 `isLockdownEnabled()`，两项成功核验后才显示系统锁已启用。不能核验时显示“无法核验”，保留运行期模式。系统启动、重启、配置恢复和主动连接开关均纳入验证；用户修改系统设置视为保护模式改变。此处为交付要求，不表示高级模式已实现或完成真机验收。[Android VpnService](https://developer.android.com/reference/android/net/VpnService)、[VPN 生命周期](https://developer.android.com/develop/connectivity/vpn)

**边界**：`0.0.0.0/0`、`::/0` 使用出口语义，不按普通前缀重叠一律拒绝。控制服务、Relay 和启动 DNS 不能递归依赖尚未建立的出口；未明确授权的内网、链路本地、管理及实例元数据地址默认排除。出口获准不等于网关所有服务获准。

### 3.6 修改访问规则

**入口与输入**：访问规则，或从设备/共享详情进入。基本编辑为“来源 → 目标 → 协议与端口 → 检查并发布”；保留高级 Allow/Deny、优先级与 JSON。

**步骤**：读取当前版本 → 编辑草稿 → 运行现有校验 → 对实际 Peer 到注册 Service 运行现有模拟 → 核对结果 → 提交更高规则版本 → 查看客户端状态 → 必要时实测。可保存的正反例断言、完整差异和历史恢复是扩展，不能写成当前发布必经按钮。

**成功与失败**：模拟显示命中规则、动作、默认动作是否生效、版本与摘要；保存成功只代表控制面接受。版本冲突时保留草稿，拉取新版本并对比后重新提交；校验失败定位字段。恢复历史内容时形成更高新版本，不回退版本或清除吊销。

**边界**：保留项目有序 Allow/Deny 及同优先级排序；不同选择器维度按现有 AND 匹配，同维度成员按规定匹配，不能在简化界面改成允许规则并集。Any/ICMP 不应显示为受到 TCP/UDP 端口限制。已有高级规则无法完整呈现时保持原内容并引导高级编辑。

新增断言至少覆盖“工作设备能访问 NAS”“访客能打印”“访客不能访问财务”“打印权限不开放网关管理口”。断言失败阻止普通发布；紧急停用和吊销优先执行，并报告受影响的正向断言，不受其阻拦。

### 3.7 停用丢失设备与清理记录

**入口与输入**：设备详情 → 停用；展示设备、关联服务和凭据的影响，沿用现有目标核对。

**步骤**：确认目标 → 执行专用停用操作 → 记录控制面撤权结果 → 跟踪接收端确认或失效边界 → 清理引用 → 如需整理列表，再删除已停用记录。删除按现有 API 核对准确设备 `name`，界面同时展示显示名称及实际确认值。

**成功与失败**：当前专用停用路径会吊销关联凭据、禁用服务、清理 presence、将地址置入隔离回收并推进相关版本。未来网关能力也必须纳入撤权。未确认的执行端显示待确认或未知，不提前宣称全网完成。

**现状与边界**：已有专用停用和后续软删除，不把通用 `admin_state` 表单赋值描述为同等完整撤权操作。已吊销凭据不能靠切回启用复活；首版再次使用走新的受控入网。Peer ID 不复用，虚拟 IP 按 Mesh 实际隔离参数回收，不能删除后立即重分配。

| 操作 | 实际含义 |
| --- | --- |
| 客户端断开 | 停止本次网络连接，保留登记身份 |
| Android 移除本地配置 | 停止 VPN 并清理本地配置与密钥；不等于控制面撤销设备 |
| 停用设备 | 撤销该 Peer 的接入及相关授权，需跟踪生效 |
| 吊销某凭据 | 按精确序列号处理，不误伤其他有效替代凭据 |
| 删除设备记录 | 对已停用设备整理管理记录，保留必要审计关联 |

### 3.8 排查“连接正常但访问不了”

**入口与输入**：设备或共享详情 → 诊断；指定来源、目标及协议端口。当前先组合控制台模拟、Linux 本地诊断与 Android 诊断页；统一向导待整合。

| 顺序 | 检查 | 不通过时的下一步 |
| --- | --- | --- |
| 1 | 管理状态、凭据、授权新鲜度 | 处理停用、过期、轮换失败或状态过旧，不盲目改 ACL |
| 2 | 名称解析、答案、实际解析器 | 检查后缀、缓存、上游和系统接管；用地址对照，不把 DNS 成功当作访问授权 |
| 3 | 规则、来源、目标、端口及版本 | 解释命中规则；修正必要标签或最小允许范围 |
| 4 | 发布、批准、客户端接受与本地路由 | 显示未批准、未支持或冲突路径，不只提示“网络错误” |
| 5 | 直连/中继、握手、丢弃与 MTU | 使用本地观测检查链路；握手成功不代表大包或业务通过 |
| 6 | 网关转发、来源验证、SNAT 与回程 | 检查转发路径，网关在线不代表 LAN 目标可达 |
| 7 | 应用监听、TLS 和应用权限 | 定位服务或应用认证；ping 不能代替业务检查 |

当前可用命令为 `peerward status`、`peerward health`、`peerward metrics`、`peerward doctor`；诊断配置可用 `doctor --config <配置文件> --json`。状态查询需要运行中的本地 Peer 管理 socket 及相应权限。现阶段没有 `peerward netcheck`，不新增同义入口掩盖已有工具。

目标输出区分静态推导、本地观测、实际探测，附时间及版本。NAT 行为需有相应测量条件，不足则显示未知；UDP 探测失败不能断言 ISP 劫持。诊断采用受限内置检查，不提供任意远程 shell 或默认端口扫描；诊断包先本地脱敏，由操作者明确导出。

### 3.9 维护、备份与恢复

**入口与输入**：运维 → 对应对象或任务。当前已有 Mesh 创建、生命周期、轮换、Relay 排空/恢复、Linux 安装备份与原生角色升级。安装维护由已登记的本地执行器实施；隔离恢复验证从部署端运行。Compose 镜像切换与恢复投产尚未接入。

| 任务 | 操作流程 | 完成条件与异常处理 |
| --- | --- | --- |
| 凭据轮换 | 查看到期或失败原因 → 按设备本地流程生成新密钥并证明激活 → 检查签名状态 → 结束旧代重叠 | 保留 Peer ID；记录每阶段，失败按原流程恢复；管理端不生成或读取设备私钥 |
| 备份 | 部署端登记范围 → 控制台登记受限执行器 → 刷新观测 → 选择安装 → 确认全部暂停服务 → 执行并查看结果 | 保存与原服务恢复分别记录；无当前预览拒绝下发。缺失 Relay 材料、未知数据库客户端或配置变化拒绝完整备份；失败与中断依原日志恢复 |
| 恢复 | 选择受信备份记录 → 本地提供离线解密身份 → 无网络独立数据库恢复 → 核对快照与在线密钥 → 清理隔离环境 | 当前仅实现隔离验证，不激活授权；源部署丢失时可使用独立验证目录。恢复投产仍须补齐恢复点后的安全对账，不能复活已核销票据或已退役身份 |
| 原生升级 | 部署端暂存签名版本并登记执行器 → 选择当前预览 → 核对角色、前后版本及修复模式 → 确认升级 → 查看回报 | 当前产物、进程或日志变化须重新预览；中断显示需要恢复，修复原因后确认继续原事务。成功须包含实际可执行文件与就绪检查；二进制回滚不等于数据库回滚 |
| Relay 维护 | 运维或中继页 → 选择主机及替代主机 → 检查与预览 → 确认排空 → 查看任务 → 按需恢复 | 替代主机须为全部受影响 Mesh 就绪；当前分配回执、宽限期与运行租约均满足后才完成。失败保留状态并按任务版本重试；不终止 Mesh、不删除密钥、不复活已吊销凭据 |
| 删除 Mesh | 核对名称和影响 → 请求删除 → 阻止新增资源 → 撤权并清理分配 → 查询持久任务 | 离线 Relay 未确认时仍显示等待；失败重试原任务，不将 HTTP 202 当作全局完成 |

Relay 任务作用于整台受管主机，要求既有 `trust_manage` 权限。排空默认宽限期 60 秒，可设 15–900 秒；替代主机的观测须在 30 秒内，分配回执版本必须一致，且凭据、运行租约及签名目录有效。预览列出受影响 Mesh 和默认主机变更；同一预览摘要与请求 ID 支持网络中断后的幂等提交。任务三十分钟超时后保留当前状态，修复原因后按新版本重试。现有连接可能重连，不承诺无损切换。恢复不自动改回默认主机。没有主机回执时显示待确认，不能把提交成功当作运行完成。

详细执行继续使用[备份恢复](backup-restore.md)、[升级恢复](upgrade-recovery.md)、[凭据轮换](key-rotation.md)和[离线恢复流程](cloud-local-deployment-plan.zh-CN.md)。不增加浏览器输入助记词即可重建信任的捷径。

Linux 备份当前支持同主机、同 Compose 项目的完整动态安装。受限执行器凭证默认三十天，
仅可访问自身交换通道；不持有普通资源读写或信任管理能力。预览观测超过三十秒不接受新任务，
任务须在十五分钟内开始；运行中失去心跳不自动转交任务。控制台可取消排队任务，运行任务必须
先按本地日志恢复。备份可能暂停当前控制台，重新打开页面后按持久任务查看结果。
本地解密私钥、离线 Root 材料和数据库密码不上传控制台，远端命令/路径也不是任务参数。
原部署已不存在时仍可在独立目录验证归档；验证成功不等于可恢复生产授权。

Linux 版本升级按“登记 → 检查配置 → 启用版本路径 → 预览 → 确认升级 → 查询结果”操作。
`peerward update register` 校验已安装产物的签名与摘要，生成可检查的 systemd 配置，不直接修改服务。
`update apply` 在安装锁下记录目标与恢复方向，实际切换后检查健康与进程可执行文件；离线文件仍须匹配签名摘要。
Peer 使用 `unix:///run/peerward/peer.sock` 等已配置的受保护接口，核对套接字所属进程，并以守护进程 UID 查询健康；不需要另开 HTTP 端口。
`update status` 查询持久阶段，历史成功不等于当前在线。中断后用 `update recover` 继续原方向，重复操作不反复交换版本。
Relay/Peer 失败可在签名回退下限内恢复上一版本；Control 失败保留目标与数据库，只允许继续恢复。
若产物本身需要修复，可显式用 `update apply --repair` 选择更新的签名版本，保留上一条失败记录；不能覆盖正在执行的事务。
Control 新迁移由新程序启动执行，旧 Control 遇到未知更高迁移会拒绝启动；不回滚数据库，也不借恢复快照复活旧授权。
控制台操作使用部署端 `register-upgrade` 固定的版本与本地材料，不提供远程命令或路径输入。
运维 → 安装维护 → 选择执行器，页面区分备份与升级影响。预览超过三十秒不可下发新升级；恢复原任务只要求同一执行器保持当前连接，不要求失败服务先恢复就绪。
普通心跳只核对日志；“核对原生升级恢复”经影响确认才增加恢复代次。同一请求重试不重复增加代次，已完成代次不再次执行。
需要更新产物修复时，在部署端暂存更高签名序号的新版本并显式登记修复配置；新事务落盘后才将匹配的旧失败任务标为已替代，保留原日志。无关或仍运行的任务不能被替代。
统一二进制不能更新 Console 独立程序。Compose 发布切换、完整真实应用跨版本验收和恢复投产仍需交付。
完整参数、状态与失败处理见[Linux 版本升级](upgrade-recovery.md#versioned-linux-roles)。

### 3.10 为自动化创建受限凭证

**入口与输入**：运维 → 凭据 → 自动化凭证。选择当前网络，填写任务名称、读取或修改普通资源的权限、有效天数（1/7/30/90；默认 30 天）。需要既有信任管理权限。

**步骤**：创建 → 复制仅本次显示的密钥到自动化系统的秘密存储 → 隐藏密钥 → 通过该网络内实际资源接口验证权限。列表按页显示名称、权限、失效时间和撤销状态；不展示数据库摘要。API 可选择 5 分钟至 90 天的期限，并可单独授予审计读取权限。

**成功与失败**：创建返回持久凭证记录与一次显示的密钥，自动化仅可访问本 Mesh 的获准接口。过期或撤销返回 401；跨 Mesh、浏览器会话、信任变更或权限不足返回 403。创建响应丢失时，列表中查找对应记录并撤销，再创建替代；系统不恢复已隐藏的密钥，也不把相同请求 ID 签发为另一把密钥。

撤销先展示使用此凭证的自动化将失败，再按版本执行；重复已完成的撤销安全返回。该操作不撤销已经生效的设备授权或修改网络配置。机器凭证与 OIDC 并存，不创建用户账户；审计操作者为 `machine:<凭证 ID>`，浏览器 OIDC 操作者使用独立的 `oidc:` 命名空间。读取权限不要求配置所有权；机器凭证要修改配置，必须先由管理员明确将当前 Mesh 的配置所有权交给它。撤销或过期不会自动恢复手动写入，管理员可显式接管。维护任务继续按独立工作包实施。

### 3.11 导出、核对并应用网络配置

**入口与输入**：运维 → 凭据 → 网络配置。默认读取当前 Mesh 的版本；导出 JSON，或选择同一 Mesh 的配置文件。高级文本编辑保留原草稿。配置文件包含资源、提供者绑定、集合、自动批准规则、DNS、设备规则和资源规则及测试；不包含设备私钥、邀请、签名租约、地址分配、实时广播或审计。

**步骤**：读取当前版本 → 导入或编辑 → 校验 → 预览变更 → 核对删除、授权、提供者及 DNS 影响 → 勾选影响确认 → 应用。资源和绑定的 UUID 仅在此高级配置流程中使用；日常操作继续选择名称。资源、集合及规则可以在一个事务中同时创建或删除，不要求逐条 API 调用。

**成功条件**：控制面返回已保存版本、配置摘要和测试结果。预览运行与应用相同的事务路径，但回滚全部写入；应用同时提交配置、审计与响应记录。未变化的声明不递增资源或配置版本；恢复旧文件生成新版本，不恢复旧身份或租约。“配置已保存”不等于客户端已应用或业务可达，继续查看对应设备回执并实际验证。

**异常与重试**：版本变化返回 `version_conflict`，草稿保留；重新读取后再次预览。预览摘要不符返回 `preview_changed`。请求标识同时绑定原操作者、原版本和配置内容；响应丢失后原样重试，返回已提交结果，不能将同一标识用于其他修改。正反例均校验；可以证明只撤权的变更不受正向访问断言阻挡，负向断言失败仍拒绝。跨 Mesh 引用、重复身份、未知字段、DNS 冲突或非法提供者使整个事务回滚。

**配置所有权**：默认手动管理，机器凭证不能写入被管理配置。管理员选择当前 Mesh 的有效读写机器凭证、确认影响后转交；此后普通手动配置修改返回冲突。设备丢失时的停用与凭据吊销不受仓库所有权阻挡，并使旧预览失效。管理员随时可明确转回手动管理；原机器凭证随即失去配置写入权。凭证不可自行取得所有权。

**仓库操作**：使用 [`scripts/peerward-config.py`](../scripts/peerward-config.py) 的 `export`、`validate`、`preview`、`apply`。环境提供控制面来源、Mesh 和受限凭证；凭证只进秘密存储。先导出 `network.json`，预览保存独立的 `review.json`，应用及重试复用该文件。脚本拒绝重定向及非回环明文 HTTP。参考[可运行工作流示例](../examples/gitops/github-actions.yml)；只在仓库运行固定客户端，控制面不运行 Git 脚本。示例默认仅预览，显式选择应用，并保留审阅产物。

### 3.12 保存和切换客户端网络

**Linux 当前操作**：先按添加设备流程取得各网络的独立配置，再用名称登记到本地私有目录。登记不复制密钥、不签发身份，也不证明设备可达。

```sh
peerward client profiles save --catalog ./saved-networks --name home --config ./home/peer.toml
peerward client profiles save --catalog ./saved-networks --name office --config ./office/peer.toml
peerward client profiles list --catalog ./saved-networks
peerward client profiles select --catalog ./saved-networks --name office
peerward peer run --catalog ./saved-networks
```

**切换顺序**：停止当前守护进程 → 如仍有持久出口阻断，先按原配置执行 `peerward client exit off --config PATH --offline` → 按名称选择 → 重新连接。通过目录运行时，目录和已登记配置的运行锁保持独占；目录列表仍可读取。运行期间拒绝修改选择，不把配置文件保存当作连接已切换。启动仍执行已有凭据、签名状态、期限和恢复校验。

**失败处理**：名称重复、损坏的目录、身份或运行路径被替换时拒绝继续，保留原记录；修复配置后重新明确登记。`profiles deactivate --catalog PATH` 清空当前选择；`profiles remove --catalog PATH --name NAME` 只移除非活动目录项，保留原配置、密钥和防回滚记录。需要退役设备时使用管理端停用流程。原 `peerward peer run --config PATH` 调用保持支持。

**Android 操作**：设置 → 保存的网络 → 先断开 → 添加另一个网络 → 确认保存，随后回到“添加设备”导入新邀请。再次进入设置可按网络名称和地址选择已有配置，再主动连接。最多保存 32 个网络；入网申请、系统权限对话框、VPN 服务或旧后台任务未结束时拒绝切换。归档保存的是 Keystore 加密配置，各网络继续使用自己的密钥与防回滚记录，不延长已签授权。删除当前本地配置只删除它的归档副本，不清除其他网络的加密密钥。当前 Kotlin/界面检查通过，模拟器切换场景待验收。


**支持范围**：Linux CLI 已实现并通过模块测试；Android 保存/切换操作仍需接入与验收。两个平台均不得通过切换或重启绕过旧授权的期限、吊销记录及系统出口保护。

## 4. 状态、异常与执行反馈

### 4.1 独立状态维度

以下为目标展示模型，不是把这些枚举直接写入现有 API。当前 Peer 展示主要包含停用、在线、离线及未报告，需要依据已有数据逐步细分。

| 维度 | 展示值示例 | 证据与约束 |
| --- | --- | --- |
| 管理状态 | 启用、停用、已删除记录 | 来自管理操作；离线不改变长期设备的管理状态 |
| 入网状态 | 待核验、已登记、拒绝、过期 | 待核验属于入网申请，不混入在线枚举 |
| 在线观测 | 在线、离线、未知 | 根据有效 presence 和最后观测时间；过旧不能一直显示在线 |
| 运行健康 | 健康、降级、重连、失败、未知 | 来自具体客户端观测；不以一次握手代表整体可用 |
| 凭据 | 有效、即将到期、轮换中、吊销、过期 | 区分精确凭据和重叠窗口，不当作整台设备唯一状态 |
| 共享 | 已配置、待批准、已批准、撤回；运行可用性单列 | 配置、授权、发布与运行事实互不代替 |

### 4.2 配置状态必须有证据

| 展示 | 允许使用的依据 | 不能据此推导 |
| --- | --- | --- |
| 已保存 | 控制面已提交相应版本 | 已签名分发或全网生效 |
| 待分发 / 已分发 | 对应 outbox、签名状态或实际投递证据 | 每个客户端收到并应用 |
| 已应用 | 目标设备对具体状态类别和版本的可信确认 | 应用端口可用或所有设备都应用 |
| 待应用 / 应用失败 | 已知应执行但尚未确认，或有明确失败回执 | 离线设备必然失败 |
| 未知 / 待确认 | 无回执、数据过期或版本无法对应 | 默认成功 |
| 实测可访问 | 指定来源到目标的探测结果、时间和范围 | 其他来源、协议或将来时刻也可访问 |

当前 SSE 用于刷新管理视图，聚合健康包含签名 revision，但尚不能据此构造全部资源的逐设备应用回执。统一确认接口与界面是扩展。页面可先显示已保存和最后观测，不造出“全网已应用”进度。

### 4.3 异常与重试约定

| 情况 | 用户反馈与恢复路径 |
| --- | --- |
| API 400 / 字段错误 | 标出具体字段，保留输入，说明可接受范围 |
| 缺少版本前置条件 428 | 重新读取对象取得版本；不去掉并发保护后强行提交 |
| 版本冲突 409 | “对象已被修改”；保留草稿，对比最新内容后重新提交 |
| 提交超时 / 结果未知 | 先查询资源或任务；仅已有幂等契约的操作复用同一标识重试。普通创建不能假定任意重发都安全 |
| 批量中任一对象过时 | 整批未提交；指出冲突对象，重新预览，不显示部分成功 |
| 控制面不可用 | 显示最后成功同步时间；有效授权可按现有边界使用，过期后停止依赖它的通信 |
| 地址池耗尽 | 指出分配与隔离状态，按安全迁移扩容或等待回收；不绕过隔离期 |
| Android 权限被拒绝 | 保留已登记配置，说明授权后可重新连接；不反复核销邀请或循环弹系统提示 |
| Mesh 切换、对象删除或权限改变 | 清理旧上下文和选择；在途响应不能更新到新 Mesh；草稿明确归属 |
| 告警被确认 | 只表示已阅读；故障恢复需新的健康证据 |

## 5. 工程模型与不能省略的约束

本节供实现与评审使用。用户日常流程使用设备、共享和访问规则等名称；内部资源名不要求逐一变成菜单、表或微服务。

### 5.1 领域职责

| 对象 | 职责与关系 | 当前基础 / 目标增量 |
| --- | --- | --- |
| Mesh | 地址、名称空间、信任、策略和审计范围 | 已有；网络设置与生命周期入口收敛 |
| Peer | 一个 Mesh 内的设备身份、元数据和能力承载 | 已有；补充能力及生命周期配置 |
| JoinTicket / 入网申请 | 接入授权与核验过程，生命周期彼此区分 | Ticket 已有；审批、预绑定及完整历史待补齐 |
| Service | Peer 所属的服务目录、协议端口和别名 | 已有；不改为虚拟服务或负载均衡资源 |
| NetworkResource | 稳定的 LAN 访问目标，首版 IP/CIDR | API、控制台及签名下发已接入；资源 ID 不等于设备密码学身份 |
| GatewayBinding / RouteAdvertisement | 获准提供者及范围 / Peer 实际发布的路径 | 已独立保存并接入 Linux 路径发布；批准来自绑定，发布者不能自己批准 |
| PolicySet / PolicyRule | Mesh 内规范规则及有序求值 | 已有；资源目标、路径约束、断言和期限按执行能力扩展 |
| DeviceSet / ResourceSet | 重复使用的受控选择范围 | 简单场景复用标签；需要时提供显式成员或简单条件，无嵌套查询语言 |
| DNSProfile / ResolverRule | 内部名称、上游、分流及适用范围 | 版本化默认/范围配置、合并预览、静态记录及执行适配已接入；完整平台验收待补齐 |
| Credential / Authority / Rotation / Revocation | 凭据、信任链、轮换与精确撤销 | 复用既有模型；Root 私钥不进入普通管理表单 |
| RelayHost / Assignment / Relay | 宿主设施、Mesh 分配和隔离的中继身份 | 已有基础；补维护和容量体验，不复制每个 Mesh 一套核心容器 |
| AuditEvent / LifecycleJob / Outbox | 审计、持久任务和可靠变更分发 | 已有基础；不能以一次 HTTP 成功代替外部步骤完成 |
| IPAllocation / Presence / RuntimeHealth | 地址生命周期及有限时效观测 | 自动维护；前台显示必要事实与时间 |
| ApprovalRule / AutomationCredential / Webhook | 可选自动批准、机器调用、通知 | 按实际需求扩展；不新增人员目录 |

Mesh 包含设备、票据、规则、服务与目标资源。资源经获准绑定关联提供 Peer，实际发布引用对应授权；出口批准保存在提供者的出口配置中，默认路由引用它，不为 IPv4/IPv6 建两份独立授权。资源与网关分离参考 NetBird，但其 Network 是基础设施配置容器，不等同于 Peerward 的 Mesh 隔离域。[NetBird Networks](https://docs.netbird.io/manage/networks)

标签由可信控制流程赋予，设备自报不能提权；资源不自动继承网关标签。显示名称、设备位置和 owner 备注均不作为授权身份。标签、集合、资源重命名或删除时检查全部引用，不静默级联删除规则；成员与地址变化须重评估授权。

### 5.2 接入、密钥、吊销

核销沿用既有事务：票据状态、claim_id、规范签名请求、Peer、地址、凭据、规范响应、审计与 outbox 一起提交。完全相同有效请求幂等恢复，冲突请求拒绝；历史响应不产生新授权，不复活已撤销身份。票据取消或过期与已经加入的设备生命周期独立。

设备 Ed25519 身份、Noise X25519 链路认证、WireGuard X25519 静态密钥分别由凭据绑定；WireGuard 短期对称会话密钥由协议栈派生。管理端展示凭据与轮换结果，不手工管理派生密钥。凭据 UUID 序列号用于精确识别，不能按大小比较“新旧代次”；目录和策略版本在各自范围比较。

吊销采用在线更新与有界有效授权共同收敛；收敛上限须覆盖状态新鲜度、凭据期限、时钟误差和执行延迟。项目已有有效期检查与防回滚基础，不能从一个截止字段推出任意“5 分钟全网生效”保证。更低版本拒绝，同版本同内容可幂等恢复但不续期，同版本不同内容拒绝；已接受吊销及时间下界跨重启保留。

新增路由、资源、临时授权和设备条件同样需要执行端过期阻断，检查直连、中继、网关、缓存和既有连接。临时实例按租约或可信观测清理，控制面失联不能直接当作设备销毁；先撤权，再隔离回收地址。限期访问到期由执行端限制，后台定时删除只是整理；其他规则仍允许时说明实际有效授权。

设备接入期限通过邀请的 `settings.lifecycle` 设置：`long_lived`（默认）、`ephemeral` 或 `expiring`（含 Unix 秒 `valid_until`）。控制台限期输入明确使用 UTC，设备详情按本地时区显示。限期设备的初始凭据和所有轮换凭据均不能晚于截止时间；本机及通信对端由共享核心检查，过期清理任务即使尚未运行也不能延长凭据。到期后需新邀请重新加入，停用或已吊销凭据不能通过改状态复活。

临时设备连续离线三十分钟才进入退役事务。只有签名发布成功且全部已启用 Relay 持续报告有效运行租约时才累计；使用进程单调时间，并校验数据库时钟间隔。控制面失败、进程/Relay 重启、观测超过十五秒未更新、时钟异常或设备重新上线都会重置计时。多个控制实例按 Mesh 协调观察者，不重复累计同一段时间。退役先撤销凭据、服务和在线记录，取消待轮换，再将两族地址放入隔离期并记录审计；界面显示退役原因。部署关闭某 Relay 前应停用其管理记录，否则无法证明完整观测，清理会保守暂停。

离线 Root 与在线 Authority 不自动抵抗在线签发方失陷。若需要独立设备核准链，另立威胁模型、签署与恢复协议，不能将现有信任管理等同于 Tailnet Lock。[Tailnet Lock](https://tailscale.com/docs/concepts/tailnet-lock-whitepaper)

### 5.3 策略与一致性

已有引擎支持 Peer、标签、CIDR、协议、端口及 Allow/Deny，保留确定排序与匹配语义。来源 CIDR 先验证地址属于合法 Peer 或获准代理范围；LAN 目标地址和承载隧道的网关 Peer 必须分别表达，不能把打印机地址塞入普通 Peer 描述就宣称完成转发模型。

接收端和网关进行权威检查。状态化返回依赖有效连接、身份及当前授权；策略、标签、凭据、期限变化时重新评估或清理相关连接状态，不能让旧 conntrack 永久绕过撤权。L3/L4 规则不区分同端口 URL 或应用管理接口。

普通修改沿用 ETag/If-Match，策略沿用单调 revision；批量按既有版本与事务约束执行。资源变更、审计、outbox 同事务提交，外部操作由可重试任务推进。单节点原子替换不等于全网同步；资源、规则、DNS 与路由依赖必须绑定版本或一致性摘要，依赖不齐时不得错误拼装授权。

基本与高级编辑共用规范模型和校验器。新选择器、到期条件或提供者约束若旧客户端无法执行，则拒绝依赖该能力的发布，不能静默丢掉字段。测试门禁只验证给定断言；权限预览显示未能计算部分，不宣称完整安全证明。Tailscale 可视编辑和 tests 提供交互参考，其 grants 语义不直接替换本项目引擎。[Visual Editor](https://tailscale.com/docs/features/visual-editor)、[Policy Tests](https://tailscale.com/docs/reference/syntax/policy-file#tests)

### 5.4 路由、隔离与高可用

路径流程分别保留定义、发布、批准、授权、分发、客户端接受、安装与业务验证。SNAT 在转发策略检查之后；保留源地址时必须配置回程，SNAT 只影响目标看到的源地址，不表示所有审计线索消失。WireGuard 加密在网关处终止，最后一段依赖应用协议。

明确区分到网关本机、经网关到 LAN、经出口到互联网三类流量。资源批准约束实际提供者和前缀，批准较小目标不自动分发整个 LAN。撤回路径后不得让受保护目标隐式改走更宽子网或未批准出口。

冲突检查针对实际可安装路径。同一站点的 /32 与包含它的 /24 可以描述同一网络；按目的地址先选最具体前缀，拒绝时不回落。完全相同前缀的多个名称统一按优先级、同优先级拒绝优先及规则 UUID 排序；允许必须对应获准提供者，另一名称不能绕过拒绝。异站点相同地址不因此成为高可用候选。普通子网与虚拟池冲突拒绝，不支持的重叠显式报错；出口默认路由另算，客户端仍检查本地 LAN、其他 VPN 与容器路由。

多网关共享同一资源记录，分别绑定、批准和发布；客户端再按当前规则过滤提供者。向导可填写优先级（默认 100，数字较小者优先，平局按稳定设备和绑定标识排序）；已有绑定可修改优先级。保存保留原批准来源，推进绑定版本并等待网关重新发布。版本冲突时保留输入、刷新绑定后重试。共享核心已接入每 5 秒一次的 WireGuard 内部路径探测：同一提供者的多个资源合并探测，三次失败后停止选择该路径；恢复连续成功并稳定 30 秒后，新连接才回切。健康备用上的既有连接保持原提供者。新路径有最多 15 秒的发现窗口，期间显示未知；过期观测不持续放行。路径探测与目标服务健康分开。资源可配置范围内固定 IP 的 TCP 探测；获准 Linux 网关每 30 秒连接一次，最多 8 个并发、单次 2 秒，不发送应用内容。设备签名上报绑定资源/路径版本，90 秒后显示未知；改址、撤回、凭据失效立即使旧观测不适用。控制台分别显示可连接、拒绝、超时、无法连接和未知，不用端口可连接替代登录验证或自动切换。每 Mesh 最多 64 个明确探测目标，默认关闭。保留源地址模式还须保证回程到达原提供者，普通静态回程路由不能据此宣称完成 HA。不承诺存量 TCP 无损、固定秒级切换或吞吐线性增长。[NetBird Routing Peers](https://docs.netbird.io/manage/networks/how-routing-peers-work)、[Tailscale HA](https://tailscale.com/docs/how-to/set-up-high-availability)

Mesh 隔离包括公钥及签名状态分发、地址准入、策略、DNS、路由和宿主转发。原生 WireGuard 报文没有 Mesh ID；Peerward 外层封装另有寻址范围，不能混为一谈。共享 Relay 不得跨 Mesh 转发；合法安装与可信执行端不得形成无控制桥接。已攻陷设备自行绕开本机客户端不属于普通配置能够阻止的保证。

Site-to-Site、LAN 主动访问 Peer、二层发现、地址映射属于独立扩展，需代理源身份和双向规则；站点改名不能解决重叠地址。

### 5.5 DNS 与连接韧性

Linux 和 Android 已有 DNS 处理，包含目录名称、服务可见性及对应平台接管逻辑；目标是补齐配置与状态。内部记录不依赖外部查询，但解析仍涉及系统调度、缓存与报文处理，不承诺“纳秒、零开销”。后缀采用安装实际配置，不统一改成 `.direct`；它是公共顶级域。自动创建已有 `.internal` 后缀，高级手工及已有安装保留原值。[IANA .direct](https://www.iana.org/domains/root/db/direct.html)

DNSProfile 首先提供 Mesh 名称、分流域、默认上游、搜索域、适用设备、出口行为与故障处理。多配置合成一份确定有效结果：较具体后缀优先，同级冲突拒绝或显式排序；私有域失败不静默送公共上游。检查 UDP/TCP DNS、路由与回程，避免上游自循环和启动依赖。自定义 LAN A/AAAA 及其他记录属于扩展，需名称冲突、别名循环、可见性和缓存失效检查。

preview.4 的实施采用受管理解析入口：Linux 先保存原有上游，再将系统管理的查询导向本地解析器；分流和静态记录读取同一份有效签名配置。明确配置的 Mesh 子域委派优先于隐式 Mesh 权威解析；默认上游或相同 Mesh 后缀不能遮蔽设备名称。搜索域由独立事务应用，退出和恢复按“DNS 子事务 → 资源事务 → 基础网络”顺序进行。发往 Mesh 设备或共享资源的 DNS 上游必须经 TUN；Android 在对应路由未安装时拒绝该查询。应用内 DoH 等绕过系统解析器的行为仍受下述边界约束。当前完成情况与未验收项见[实施清单](management-implementation-status.zh-CN.md)。

Peer 主机名与 Service 别名统一校验；显示名和 DNS 名分开，后缀迁移展示影响。应用内 DoH、Android Private DNS 与系统 DNS 的交互逐平台验证；系统接管不等于所有应用查询受控，DNS 成功也不自动授予网络权限或受信任 TLS 证书。[NetBird DNS](https://docs.netbird.io/manage/dns)、[Tailscale DNS](https://tailscale.com/docs/reference/dns-in-tailscale)

直连和中继已共享路径无关的 WireGuard 会话；保留既有并行探测、有效路径验证、回退和 MTU 机制，不新建第二套连接管理器。签名端点声明不代替真实双向路径验证；小包能直连不保证大包也能，必要时仍可用中继。已认证中继减少等待，但仍有链路和 WireGuard 握手前提，不承诺首包 0-RTT。[连接协议](protocol.md)、[路径协调规范](../spec/WIREGUARD_COORDINATION.md)、[Tailscale Connection Types](https://tailscale.com/docs/reference/connection-types)

### 5.6 运维、容量、恢复和自动化

RelayHost、Mesh Assignment 和 Relay 身份分开管理；STUN 发现与 Noise Relay 分开诊断，不宣称兼容 DERP/TURN。Relay 不持有 WireGuard 内层解密私钥，但能观察必要端点元数据、时间和长度，不描述成完全不可见或仅按 Session ID 转发。

控制台沿用当前聚合观测边界：有限时效健康、Peer 到 Relay presence 和 Relay 骨干。当前 `relay_packet_share_bps` 是以基点表示的包数占比，`presence_count` 是在线记录数量，均不是带宽或费用。新增容量指标需注明时间窗、字节口径、分母和来源；未测量显示未知。控制面、数据库、审计备份、Relay 流量、网关容量和维护时间分别评估，不移植竞品吞吐或成本数字。

运维页现在按“待处理事项 → 容量 → 主机维护 → 安装备份”组织。进入后自动加载，容量按主机名称选择，每五秒刷新已存采样；主机每十秒通过现有 mTLS 上报。三十秒内有效显示“采样有效”，过期、访问失败或未接入显示未知。容量卡片分别展示已接纳 Peer 会话、实际承载读取/接受写入字节、Peer 消息队列和骨干/审计队列槽位。下拉切换后清空旧主机结果，原响应不能覆盖新选择。

普通操作只需选择主机、查看事项并进入对应检查：队列拒绝先检查带宽与慢客户端；审计丢弃先查数据库与写入负载；主机未知先检查管理连接；维护失败进入任务重新预览；恢复未完成回到登记的部署主机执行受限恢复。控制台不把最新一次的计数器差值用于长期趋势判断，进程重启后等待新的统计基线。详细累计计数、进程标识和采样时间保存在技术详情。查询使用真实 `GET /api/v1/relay-hosts/{host_id}/capacity` 与 `GET /api/v1/operations/status`，沿用信任管理权限。

运维摘要显示审计实际存储字节与 PostgreSQL 估计行数/增长；没有增长基线时显示“—”。备份结果注明执行器来源，未提供回报不显示成功；一次备份成功不代表完成恢复验证。Prometheus/Grafana 模板同步覆盖实际帧字节、队列、审计丢弃和审计采样有效性，仍不把累计帧字节换算成费用。详见[容量实现记录](management-implementation-status.zh-CN.md#linux-容量观测与运维状态2026-09-14)。

审计引用既有可信操作者、设备或系统任务，记录对象、变更、结果、时间及请求标识；禁止记录票据秘密、私钥或业务明文。保持当前审计无自动保留清理的约束，配套容量、备份与受控归档；数据库只追加约束不等于数据库最高权限也无法篡改。配置审计不承诺溯源病毒，不默认增加长期 Peer 通信关系或 DNS 查询明细采集。[可观测性](observability.md)

备份覆盖一致数据库、匹配在线秘密与部署配置；离线 Root 恢复材料分开保管，设备私钥由设备侧保护。恢复演练核对安全状态与宿主网络恢复，发布证据必须绑定版本、平台及产物，不引用历史报告直接承诺当前安全。所有列表、集合展开和签名配置保留容量限制，超限拒绝，不截断为更宽规则。

自动化复用当前 API 校验、版本和审计。受限机器凭证按 Mesh、操作、期限管理，不共享永久全局凭据。声明式配置先限规则和管理配置，不覆盖运行会话、地址租约、审计或私钥；管理范围明确由控制台或外部仓库拥有，避免 GitOps 静默覆盖紧急修改。Webhook 默认关闭，目标经配置后才发送许可事件，带验证、去重、重试与失败队列，不阻塞数据面；目标与重定向限制共同防止越权访问。[Tailscale GitOps](https://tailscale.com/docs/gitops)、[Webhooks](https://tailscale.com/docs/features/webhooks)

**Webhook 操作**：运维 → 凭据与配置 → Webhook 通知 → 填写名称、HTTPS 接收地址并选择事件 → 保持关闭并核对详情中的验签公钥 → 接收方配置验签和持久去重 → 确认地址归属并启用 → 查看交付状态。失败记录可按当前版本重试，过时或停用的通知配置先处理配置状态。编辑会取消旧版本队列；已发送的消息无法撤回。发送成功、接收方持久接纳、下游业务完成是不同状态，当前控制台只观测 HTTP 交付结果。[接收示例与边界](../examples/webhooks/README.zh-CN.md)


自动批准入口位于“网络共享 → 自动批准路径”。先在“访问规则”中创建设备集合，再选择已有资源所代表的站点，填写明确 CIDR；新规则默认停用，检查影响后启用保存。一次规则只覆盖所选站点和完整包含的目标网段，第一版仅自动批准 SNAT 私网路径，保留源地址和互联网出口仍由管理员确认。批准不创建访问规则，也不替代网关发布和实际连通验证。

规则、设备标签或集合成员变化会在同一数据库事务内重新评估批准，并保存来源规则及版本。多条规则匹配时按稳定规则标识排序；收紧或删除某条规则后，其他有效规则仍可授予批准。人工批准独立于自动规则；人工撤回会移除该路径的自动评估资格，规则更新不会恢复它。需要恢复时，在提供设备卡片点击“按当前自动规则评估”。资源改址也要求重新授权。保存或请求遇到版本冲突时保留草稿，刷新后核对当前影响再重试。

已知安全缺口随对应场景处理，不因 UI 排期靠后而延期。若 P0 接入场景要求抵抗票据泄露抢用，应提前交付可信预绑定或核验审批，不能用 P2 排期作为豁免。设备条件证据需有来源与有效期，未知不按通过；隔离设备必须有统一准入限制，不能只加一条可被其他 Allow 覆盖的规则。

### 当前实施补充：期限与名称保留

Mesh 查询返回 `lease_seconds`，现有 `PATCH /api/v1/meshes/{mesh_id}` 支持 300、900、3600 秒，默认 900 秒；修改期限需要既有 `trust_manage` 能力和版本前置条件。普通续签不清空连接；期限改变由执行端清理旧连接和排队报文。已经失联的设备无法获知期限缩短，仍按此前已签署租约的截止时间停止通信。

设备名、服务别名、内部静态 DNS 名称和一级子域委派共享原子保留；冲突拒绝保存，Mesh 后缀改变同样重新校验。删除资源前须移除当前规则和保存测试的引用，历史内容保留。上述路径、测试与剩余问题见[实施清单](management-implementation-status.zh-CN.md)。

### 双地址与集合的本轮实现口径

设备和资源集合在“访问规则”中维护：选择类型、名称、显式成员，可增加受控标签条件；成员为显式选择与标签匹配的并集，所有标签条件须同时满足，空集合不授权。基础编辑可分别选择来源设备集合、目标资源集合；对应的具体设备与资源用于模拟样例。编辑集合后重新载入规则版本并运行测试；成员变化自动进入签名配置，执行端应用后失效旧连接，不让正向断言阻止撤权。集合上限为 64，每个集合最多解析 4096 个成员，超限拒绝；有当前规则引用时不可删除。

默认 Mesh 使用 IPv4 /24 和独立 ULA IPv6 /64；高级模式保留主池配置语义，控制面分配另一地址族的独立地址池。新设备的两地址在同一核销事务中分配并随原响应幂等恢复，不按地址创建两台设备。签名目录分别认证两地址，密钥及设备身份不因此复制。客户端仅安装已分配族的路由，资源模拟按具体目标的地址族选来源地址，A/AAAA 分别返回。实现和验证范围以[实施状态](management-implementation-status.zh-CN.md)为准，当前不据此宣称双栈出口已完成。

保存网络补充：Android 可在连接完全停止后选择配置、保存并接入另一网络，或移除非活动保存项（包括损坏归档）。移除保存项保留设备密钥与信任历史，不等于停用或吊销；需要撤权时在控制台停用设备。当前选择只能使用既有的断开/移除配置流程处理。

配置重试响应与管理历史：邀请及核验决定不随运维短期清理删除；入网公开凭据响应继续绑定原申请。配置应用的完整响应保留 30 天，之后由有界维护批次压缩，保留原请求标识、操作者及摘要。相同请求在压缩后返回 `410 configuration_response_archived`，需读取当前配置、重新预览并使用新请求标识。修改内容重用旧标识仍拒绝；10,000 条容量限制针对尚未压缩的响应，不能通过删除幂等标识腾出空间。长期历史和审计的磁盘增长需要容量监控及备份。

Linux 保存网络的切换还检查旧配置的出口、路由、DNS 和宿主网络恢复日志。崩溃留下任一日志时，先在原网络环境执行 `peerward client exit off --config PATH --offline`，完成独立对象恢复后再选择另一配置；界面记录或 CLI 选择不能代替实际清理。
